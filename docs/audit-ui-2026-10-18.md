Metode: pemindaian kode (grep) + skrip pengukur di browser (warna hasil render, rasio kontras WCAG, tinggi tombol/input, radius/padding kartu) pada 12 halaman + login, mode light dan dark. Tanpa screenshot.

## 4. Rekomendasi urutan perbaikan

1. **Satukan token warna** (perbaikan terbesar, sekali jalan):
   - Pilih satu palet dark: navy (seperti sekarang) atau netral, lalu tulis ke variabel shadcn (`--background`, `--card`, `--muted-foreground`, `--border`, …).
   - `--primary` → #2563EB; `--destructive` → #DC2626 (light) dan merah yang lebih terang untuk teks di dark.
   - Petakan `text-text-secondary-light` → `text-muted-foreground`, `bg-card-light dark:bg-card-dark` → `bg-card`, dst. lewat find-and-replace, lalu hapus token `-light/-dark`.
   - Ini menyelesaikan ±80% kegagalan kontras dark mode tanpa menyentuh logika halaman.
2. **Tetapkan skala ukuran**: tombol `sm` 32 / `default` 40 / `lg` 44; input 40; radius kartu satu nilai (mis. `rounded-2xl`), dialog/tombol `rounded-lg`.
3. **Buat `PageLayout` + `PageHeader`** (judul, deskripsi, slot aksi, lebar maksimum opsional), lalu terapkan ke 14 halaman.
4. **Lengkapi dan pakai komponen**: `Card`, `Table`/`DataTable`, `Badge` dengan varian status (success/warning/danger/info), satu varian CTA primary (pilih solid atau gradient).
5. **Migrasi per fitur** (opname, stock-out, reports, stock-in, products/services, users, dashboard, notifications/profile) — bisa paralel karena antar fitur tidak saling sentuh.
6. Audit ulang dengan skrip yang sama, termasuk Pelaksanaan/Detail Opname dan dialog.
